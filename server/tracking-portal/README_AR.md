# بوابة متابعة صيانة NEXVARY MR — حزمة السيرفر

هذه خدمة متابعة خاصة بمركز صيانة واحد وبرنامج Windows ناشر واحد. تعرض حالة الإصلاح للعميل عبر رابط خاص، وتستقبل المزامنة عبر مفتاح سري منفصل. ليست منصة لإدارة العملاء على السيرفر، ولا تتطلب فتح منفذ في كمبيوتر المركز أو إبقاء الكمبيوتر متاحًا من الإنترنت.

## التثبيت

الأنظمة المستهدفة: Ubuntu 22.04/24.04 أو Debian 12/13، مع systemd وPython 3.10 أو أحدث، ومعالج x86_64 أو arm64. يلزم نطاق فرعي تملكه مثل `tracking.example.com`، وسجلا A وAAAA صحيحان عند استخدام IPv6، ووصول TCP إلى المنفذين 80 و443، واتصال HTTPS صادر لتنزيل الاعتماديات والتحقق من الشهادة. لا تنشئ سجل AAAA لخادم لا يملك IPv6 صالحًا. استعمل DNS مباشرًا أولًا؛ لم تُضبط هذه الحزمة للعمل خلف CDN إضافي.

انقل ملف `NEXVARY-Portal-Setup.sh` إلى السيرفر، ثم استبدل النطاق والبريد الحقيقيين:

```bash
bash NEXVARY-Portal-Setup.sh --domain tracking.example.com --email admin@example.com --dry-run
sudo bash NEXVARY-Portal-Setup.sh --domain tracking.example.com --email admin@example.com
```

السكربت يرفض استبدال خدمة موجودة على المنافذ المطلوبة أو ملفات غير مُدارة باسمه. لا يغير SSH أو الجدار الناري، ولا يوقف nginx/Apache أو يستبدل إعداداتهما. إذا كانت المنافذ مشغولة، استخدم سيرفرًا مستقلًا أو جهّز تكامل reverse proxy منفصلًا؛ لا توقف مواقعك عشوائيًا. قد يلزم فتح 80/443 من لوحة مزود VPS والجدار الناري الموجود قبل التثبيت.

ينشئ السكربت مستخدمين بلا تسجيل دخول، وبيئة Python معزولة، ونسخة Caddy مثبتة ببصمة SHA256، وHTTPS تلقائيًا، وخدمتين systemd، ونسخ SQLite احتياطية يومية محلية. يعرض نجاح الجاهزية فقط بعد استجابة HTTPS بشهادة موثقة. أي فشل DNS/شهادة/خدمة يعني أن التثبيت لم يجتز التحقق، حتى لو أُنشئت الملفات.

## الربط ببرنامج Windows

بعد نجاح التثبيت يوجد ملف سري بصلاحية root فقط:

```
/root/nexvary-portal-client-credentials.json
```

انقله عبر قناة آمنة إلى كمبيوتر المركز. داخل NEXVARY-MR افتح **مركز الصيانة والعملاء ← متابعة العميل ← بوابة الإنترنت HTTPS**، واقرأ نطاق السيرفر، ثم وافق على رفع حقول المتابعة العامة واستورد الملف. لا ترسله إلى العميل، ولا تنشره في GitHub أو واتساب عام أو مجلد مشترك. برنامج Windows يحفظه باستخدام DPAPI للمستخدم الحالي؛ لا يظهر المفتاح في الواجهة أو سجلات المزامنة. نسخة Linux للاختبارات تحفظ إعدادًا محليًا بصلاحيات مالكه، وليست نشرًا مكتبيًا متعدد المستخدمين.

بعد اختيار أمر الصيانة والموافقة على المشاركة، أنشئ الرابط. لا يتاح زر النسخ حتى يؤكد السيرفر نشر آخر التغييرات. يفتح العميل الرابط من أي شبكة بعد نشر النطاق ونجاح HTTPS. تتحدث البيانات عند تغيير الحالة وكل 30 ثانية أثناء تشغيل برنامج المركز؛ آخر وقت مزامنة ظاهر للعميل. يستمر السيرفر بعرض آخر حالة عند إغلاق Windows مؤقتًا، ثم يخفيها بعد 6 ساعات دون مزامنة. هذا ليس بثًا مباشرًا من هاتف العميل.

إلغاء الرابط أو تغييره يصل إلى السيرفر بعد نجاح المزامنة؛ عند انقطاع الشبكة لا تعتبر الإلغاء منفذًا على السيرفر. ألغِ الرابط وانتظر تأكيد النشر قبل إزالة الربط. إزالة الربط المحلي لا تحذف بيانات السيرفر فورًا؛ نافذة الست ساعات أو انتهاء الصلاحية، أيهما أقرب، تبقى مطبقة.

## البيانات والحدود

- المرفوع فقط: مرجع أمر الصيانة، الشركة والموديل، الحالة، سجل حالاتها حتى 100 حدث UTC، الرسالة المخصصة للعميل، بصمة رمز الرابط وصلاحيته. لا تُرفع أسماء العملاء أو هواتفهم أو التسلسل أو الأعطال أو الأسعار أو الفني أو الملاحظات الداخلية.
- رابط العميل يحمل 256 بت عشوائية؛ يحتفظ السيرفر ببصمته فقط. كل من يملك الرابط يمكنه فتح الحالة؛ لا ترسله لشخص آخر. لا تخزن مفاتيح الربط أو مسارات الروابط في سجلات وصول عامة. الحزمة تعطل access logs وتنقح عنوان الطلب والترويسات من سجلات Caddy.
- المزامنة تستبدل لقطة الروابط النشطة بمعاملة SQLite ذرية، مع هوية ناشر ثابتة وفحص revision يمنع تحديثًا متأخرًا من استبدال نسخة أحدث. ليست مزامنة دمج من عدة فروع أو أجهزة ناشرة. لا تستنسخ ملف الربط مع قاعدتين مختلفتين.
- حتى 2000 رابط نشط و4 MiB لكل لقطة. توجد حدود للطلبات والمهل والذاكرة. القاعدة المحلية على السيرفر تحتوي بيانات متابعة عامة محدودة، لكنها ليست محمية من root أو اختراق السيرفر. استخدم تحديثات أمنية ونسخًا خارج السيرفر؛ هذه ليست حماية DDoS أو اعتمادًا أمنيًا مستقلاً.
- لا يوجد QR في هذه الدفعة؛ المشاركة عبر الرابط الفعلي. لا يوجد دفع إلكتروني أو حساب عميل بكلمة مرور أو إدارة ملفات العملاء من الإنترنت.

## التشغيل والنسخ الاحتياطي

```bash
sudo systemctl status nexvary-portal.service nexvary-portal-tls.service
sudo systemctl start nexvary-portal-backup.service
sudo systemctl list-timers nexvary-portal-backup.timer
```

البيانات: `/var/lib/nexvary-portal/portal.sqlite3`. الإعداد: `/etc/nexvary-portal/settings.json`. شهادات TLS: `/var/lib/nexvary-portal-tls`. النسخ المحلية: `/var/backups/nexvary-portal`؛ يحتفظ النظام بآخر 14 نسخة. هذه نسخ على نفس السيرفر، قابلة للفقد عند فقدانه؛ انقل نسخًا مشفرة إلى مكان مستقل. لا تعرض مجلد النسخ على الويب.

الترقية من حزمة جديدة تحافظ على مفاتيح النشر وهوية المركز والبيانات:

```bash
sudo bash NEXVARY-Portal-Setup.sh --domain tracking.example.com --email admin@example.com --upgrade
```

تُحفظ نسخة الإصدار والإعداد السابقين، وتُستعاد الخدمات السابقة عند فشل تفعيل الإصدار الجديد. لا يحذف السكربت الإصدارات السابقة أو قاعدة البيانات.

لتدوير المفتاح عند فقدان ملف الربط، اختر مجلد إخراج جديدًا ثم أعد تشغيل API واستورد الملف الجديد في Windows:

```bash
sudo /opt/nexvary-portal/current/venv/bin/python /opt/nexvary-portal/current/portal_admin.py --config /etc/nexvary-portal/settings.json rotate-key --directory /root/new-portal-credentials
sudo systemctl restart nexvary-portal.service
```

للاستعادة، أوقف مؤقت النسخ الاحتياطي أولًا، ثم خدمة النسخ وAPI، حتى لا يكتب أي منهما إلى SQLite أثناء الاستبدال. يرفض أمر الاستعادة العمل ما دامت إحدى هذه الوحدات نشطة. استعمل نسخة معروفة تخص هذا المركز. تُحفظ الملفات الحالية قبل الاستبدال. لا تُعاد الروابط الملغاة من النسخة القديمة: تُفرغ بيانات الروابط عند الاستعادة وتُنشر الحالة الحالية مجددًا عند مزامنة Windows.

```bash
sudo systemctl stop nexvary-portal-backup.timer
sudo systemctl stop nexvary-portal-backup.service nexvary-portal.service
sudo /opt/nexvary-portal/current/venv/bin/python /opt/nexvary-portal/current/portal_admin.py --config /etc/nexvary-portal/settings.json restore /var/backups/nexvary-portal/REPLACE_WITH_REAL_BACKUP.sqlite3 --confirmed-service-stopped
sudo systemctl start nexvary-portal.service
sudo systemctl start nexvary-portal-backup.timer
```

لا تمرر علامة التأكيد مع خدمة قيد التشغيل. لا تقبل ملفات نسخ احتياطية مجهولة. احتفظ كذلك بإعداد المركز وملف ربط آمن مستقل؛ قاعدة المتابعة ليست بديلًا لنسخة قاعدة صيانة Windows.

## المراجعة والاختبارات

الاعتماديات المراجعة في 2026-10-18: [Gunicorn 26.2.0](https://pypi.org/project/gunicorn/26.2.0/) بعجلة PyPI مثبتة بالبصمة داخل `requirements.lock`، و[Caddy 2.11.7](https://github.com/caddyserver/caddy/releases/tag/v2.11.7) ببصمتي حزمتي Linux x64/arm64 المثبتتين في السكربت. تُنزل هذه الحزم من مصادرها الرسمية عند التثبيت؛ لا توجد أوامر `curl | bash` عائمة أو مفاتيح مسبقة داخل الحزمة.

ترخيص [Gunicorn](https://github.com/benoitc/gunicorn/blob/26.2.0/LICENSE) هو MIT، وترخيص [Caddy](https://github.com/caddyserver/caddy/blob/v2.11.7/LICENSE) هو Apache-2.0. لا يتضمن ملف التثبيت نسخة من كودهما أو ثنائياتهما؛ ينزلهما إلى السيرفر بالإصدارات والبصمات المحددة. تُحفظ معلومات ترخيص Gunicorn ضمن حزمة Python المثبتة. راجع شروط المصدر ومكونات Caddy عند إعادة توزيع الثنائيات بدل تنزيلها من المصدر الرسمي.

راجع نتائج HEAD الفعلي في GitHub Actions. اختبارات الوحدة لا تثبت نجاح DNS أو إصدار شهادة لنطاقك. وضع `--local-test` خاص بفحص CI على `portal.localhost` و9443 بشهادة CA محلية دون إضافتها لثقة النظام؛ ليس نشرًا عامًا، ويجب عدم الخلط بين نجاحه ونجاح شهادة ACME على نطاقك.
