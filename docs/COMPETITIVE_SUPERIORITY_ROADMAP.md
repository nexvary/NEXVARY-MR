## Fair comparative benchmark protocol

1. Select one exact supported capability and versions/editions, authorized license, hardware/OS and settings. Keep acquisition and analysis comparisons separate.
2. Freeze a lawful synthetic/consented populated corpus and independent expected answers, including malformed, missing, conflicting and timezone-ambiguous data. Retain dataset/tool/config SHA-256 and provenance separately.
3. Use the same input bytes and comparable settings; publish supported/unsupported/excluded inputs and reasons. Separate cold/warm runs and offline/network conditions. Do not compare a bounded NEXVARY sample against a full commercial ingest as equivalent work.
4. Measure correct/incorrect/missing artifacts, false relationships, source preservation, failure/cancel/restart behavior, wall time, peak memory and reviewer effort. Disclose incomplete and negative runs.
5. Have an independent reviewer reproduce raw outputs and calculate the metric. A result requires method, raw output hashes, exact scope, repeat count and uncertainty; an internal unit test alone is insufficient.
6. State a narrow result only after review, for example a specific metric on a named corpus/version. No overall product superiority, certification or government adoption claim follows from that result.
