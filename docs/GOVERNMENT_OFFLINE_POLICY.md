# Government application operation policy

Implemented in the Government continuation from remote HEAD 17ef2fa. Exact executable/test source and verification receipts belong in DEVELOPMENT_STATE.md; this guide alone is not verification.

## Default and operator workflow

The shipped application constructs one native `GovernmentOperationPolicy` before its consumers and attaches it before entering the event loop. All six categories start denied, including when protected workshop cloud credentials already exist. Changing Government/Professional workspaces never changes these permissions. The native gates remain effective when an action is invoked directly rather than through a disabled button.

Administration → Government operation policy (also Professional Settings) shows the categories. A currently authenticated **local administrator** must supply a reason (1–256 UTF-16 code units), explicitly approve and grant each category. Existing per-operation source/owner/device-component/network consents and compiled production/laboratory restrictions still apply. This does not grant case access or device authorization. Where the existing protected local identity is unavailable, exceptions remain unavailable (fail closed); synthetic test identity is not a production credential fallback. Grants belong to the administrator session; delegated investigator/technician exception approval is not implemented.

Exceptions last at most **ten minutes** on a monotonic application clock, and end on logout, sign-in/identity change, password rotation, observed account invalidation or application exit. Grants are never saved. Anyone can close an exception or all exceptions. Reasons, principal and displayed UTC expiry are transient operational context, **not a durable or signed policy audit record**. The persistent header, title and panel distinguish default denial from temporary exceptions.

Each new governed operation rechecks the native permission and local session. While grants exist, a one-second event-loop monitor checks expiry/account invalidation. Direct logout/revoke notifications are synchronous; worker shutdown is cooperative, with existing process kill/deadline paths. This is not instantaneous revocation under a stalled process/event loop. Already transmitted bytes, published remote state, browser launches or device/database changes cannot be undone. An expired grant cannot be used merely because its monitor event has not yet run.

| Category | Governed boundary | Revocation / restart behavior |
|---|---|---|
| `cloud-publish` | Workshop public-field HTTPS client; credential-import-triggered sync, GET and POST, received-result handling, link issuance/copy | Stop periodic/debounce timers; disconnect/abort/delete active reply; clear in-sync status. Regrant does not automatically publish. User must sync, import approved credentials or explicitly issue a link. Existing remote copies are not withdrawn. |
| `tracking-portal` | Workshop HTTP listener, including loopback, link issuance/copy, connection accept and request response | Close listener and abort accepted clients. Regrant does not restart it. Existing private-address/consent checks remain. |
| `signature-update` | User-installed FreshClam child through SecurityBridge | Cancel running worker; reject a cancelled/late success. No rollback of databases already replaced. Separate from file analysis permission. |
| `device-tools` | ToolBridge foreground and background ADB/fastboot, device-service dispatch, PowerShell USB/PnP inspection; scrcpy preflight, monitoring and launch | Stop automatic refresh; kill/cancel foreground host operation, stop owned mirror. No automatic restart/reconnect. Device changes already started require review. |
| `external-analysis` | User-installed ClamAV scan and TSK `mmls` partition child | Cancel associated worker/host process; refuse cancelled scan verdicts. TSK retains its existing checked-copy/cancel/persistence path. Native local parser jobs are unaffected. |
| `external-links` | All current QML external-link buttons routed to native HTTP/HTTPS browser handoff | Deny new handoffs; reject other schemes and embedded credentials. Cannot close/contain a browser already launched. |

Permissions are category-level exceptions, **not per-origin network allowlists or executable attestations**. Cloud retains its existing approved HTTPS origin/TLS/manual-redirect behavior. FreshClam retains the existing generated configuration. A permitted external executable may use its own network/configuration; version strings and hashes do not prove it trustworthy. Browser HTTP permission can contact any selected valid HTTP/HTTPS host. Review the particular tool/destination before granting.

## Local operations and boundary inventory

Case management, protected storage/backups, evidence SHA-256 verification, original/working-copy checks, authorized retained-report indexing, timeline, native SQLite/JSON/text/CSV/log/ADB inventory, PCAP/EXIF/firmware analysis and synthetic training do not require these exceptions. The deployed first-party `mr_evidence_import_worker` remains permitted: it has a fixed local-file adapter protocol, copied evidence, limits, cancellation and deadline. It has no application network request path, but it is a regular child process rather than an OS sandbox.

Reviewed source boundaries: `CloudTracking.cpp` Qt HTTP client; `TrackingPortal.cpp` TCP server/socket replies; `ToolBridge.cpp` and `DeviceServices.cpp` device processes; `MirrorSession.cpp` ADB/scrcpy; `SecurityBridge.cpp` scanner/updater workers; `TskImage.cpp` external analyzer; `EvidenceImportRunner.cpp` first-party adapter child. `main.cpp` has one explicit synthetic-smoke loopback HTTP client only, after the same administrator portal grant. Current QML contains no direct `Qt.openUrlExternally` call after migration; buttons delegate through Main to the policy. Component unit harnesses may omit native policy injection to test pre-existing engines in isolation; the shipped main composition always attaches it, and explicit integrated gate tests use that composition or real bound consumers.

**Not implemented/verified:** OS firewall rules, network namespaces/AppContainer, descendant process-tree containment, arbitrary privileged or modified executable control, kernel/device-driver isolation, mapped/UNC/FUSE/SMB/network filesystem containment, OS TLS/DNS/proxy/PAC traffic, browser activity after launch, executable/dependency attestation, per-destination exception rules, controlled removable-media/export policy, signed persistent policy decisions or complete air-gap enforcement. Existing local paths can refer to OS-mounted shares; file dialogs/metadata/config/PATH inspection are not a network-filesystem sandbox. Do not label the application gate “no packets” or institutionally accepted air-gap containment.

Independent institutional/OS network-capture tests, clean Windows 10/11 and authorized physical-device tests remain acceptance gates. No commercial competitor was run or superiority established.

## Reproducible checks

`mr_offline_tests` uses synthetic local identities, loopback sockets and a controlled native executable fixture, never a real phone/public endpoint. It tests startup denial, role/reason/consent/category negatives, monotonic expiry, restart, external account revocation, listener/client abort, child launch absence via marker files, permitted device/scanner/updater execution and running-worker revocation. `mr_cloud_tests` adds saved credentials with zero loopback requests while denied, explicit sync, a received GET held pending during logout and no unsolicited resume on regrant. Existing cloud TLS/redirect tests remain required.

Qt Quick exercises actual grant/revoke buttons, non-admin denial, logout clearing, AR/EN at 840/1366/1536 widths, 100/125/150% DPI and header stability. These component tests share the real policy/identity controller; existing component engine fixtures remain separate. The actual deployed EXE smoke binds all five consumers, asserts denied startup API calls, explicitly grants/revokes only its synthetic loopback portal, then runs native local recovery/import/index while default-denied. Portable and installed smoke require the policy JSON receipt and real AR/EN captures. Windows packaging includes this guide.
